# AI Usage Monitor

Codex·Claude의 **5시간·주간 한도에서 남은 사용량과 초기화까지 남은 시간**을 보여주는 작은 Windows 데스크톱 앱입니다. Gemini CLI의 모델별 한도 조회도 실험적으로 포함합니다.

## 기능

- 두 서비스의 사용량을 가로 한 줄 또는 서비스별 두 줄로 표시
- 비활성 서비스 칸을 숨기고 창 크기 자동 축소, 조작 버튼 목록 접기·펼치기
- 남은 비율에 따라 사용량 바와 퍼센트의 색상을 다섯 단계로 변경
- GPT·Claude 로고, 최상단 고정, 비율을 유지하는 창 크기 조절
- 여러 모니터 사이의 좌우 이동과 화면 경계 제한
- 트레이로 숨기기, 트레이에서 창 복원·캐릭터 선택·종료
- 사용자 제공 이미지로 만든 EXE·트레이 아이콘, 작업표시줄에는 표시하지 않는 창
- 서비스별 활성화·비활성화 및 공식 CLI를 이용한 브라우저 수동 로그인
- Gemini 아이콘과 실험적 모델 한도 조회(기본 비활성)
- 창 테두리를 따라 이동하고 모서리에서 회전하는 캐릭터 애니메이션
- 오리와 아기 펭귄 세 종류를 선택할 수 있습니다.
- Codex 개인 Pro에 주간 한도만 있으면 가로 창을 한 칸 줄입니다. 세로 모드의 너비는 가장 넓은 서비스 행을 따릅니다.
- 확인된 요금제는 서비스 이름 아래, 전체 명칭은 마우스를 올렸을 때 표시합니다. Gemini는 Code Assist 등급을 사용합니다.
- 아이콘이 번갈아 회전하고 잔량 바에 짧은 빛이 지나갑니다. 트레이에서 효과를 끌 수 있으며, 창을 숨기면 애니메이션 타이머도 멈춥니다.

| 남은 비율 | Codex | Claude |
|---|---|---|
| 80~100% | 청록 | 주황 |
| 60% 이상, 80% 미만 | 연두 | 금색 |
| 40% 이상, 60% 미만 | 노랑 | 살구 |
| 20% 초과, 40% 미만 | 주황 | 분홍 |
| 0~20% | 빨강 | 빨강 |

## 실행 조건 및 사용량 조회

Windows x64와 인터넷 연결이 필요합니다. Codex 및 Claude Code는 해당 CLI에서 로그인한 계정으로 조회합니다. Claude Desktop 단독 로그인은 배포판에서 지원하지 않습니다. 조회 제한이 걸리면 서버가 안내한 시간까지 기다립니다.

## 서비스 선택과 수동 연결

오른쪽 **메뉴 버튼**을 펼친 뒤 **사슬 아이콘** 버튼을 누르거나, 대시보드 우클릭 또는 트레이의 **서비스 연결 관리**를 엽니다.

- Codex·Claude 체크박스로 각각 활성화·비활성화합니다. 비활성 서비스는 진행 중인 조회를 취소하고 이후 사용량 조회를 멈추며, 대시보드에서 해당 칸을 완전히 숨깁니다. 남은 서비스 수에 맞춰 글자 배율은 유지하고 창 크기만 줄입니다.
- 기본 배율·메뉴 접힘 상태에서 두 서비스는 가로 1030×50, 한 서비스만 켜면 530×50입니다. 세로 모드도 하나만 켜면 빈 줄 없이 한 줄로 줄어듭니다. 두 서비스 모두 끄면 290×50 안내와 메뉴를 남깁니다.
- 조작 버튼은 기본적으로 접혀 있습니다. 메뉴 버튼을 누르면 핀·가로/세로·캐릭터·연결·최소화·종료 버튼이 나타나고, 다시 누르면 접힙니다. 메뉴를 펼치거나 접어도 글자 크기와 창 높이는 유지합니다.
- 활성화 선택은 `%LOCALAPPDATA%\AIUsageMonitor\settings.json`에 저장되어 다음 실행에도 유지됩니다. 이 설정 파일에는 인증 정보를 저장하지 않습니다.
- 자동 연결이 되지 않으면 해당 서비스의 **브라우저 로그인**을 누릅니다. 설치된 공식 Codex CLI의 `codex login` 또는 Claude Code의 `claude auth login`을 로그인할 때만 실행합니다. 배포 폴더에서 실행 중인 모니터를 종료하고, 같은 폴더의 `AI Usage Monitor.exe`와 `AI Usage Monitor.zip`을 교체합니다. 받는 사람에게는 ZIP 하나를 보내세요.
- 이 수동 로그인에는 해당 공식 CLI가 설치되어 있어야 합니다. PATH·사용자 설치·npm 설치 위치를 자동 탐색하며, 없으면 화면의 공식 설치 안내를 이용할 수 있습니다. CLI를 자동 설치하거나 EXE에 포함하지 않습니다.
- 브라우저에서 로그인한 계정은 해당 CLI에도 적용됩니다. Codex는 이 로그인 호출에만 파일 저장 설정을 적용합니다. 모니터는 비밀번호나 토큰을 직접 입력받지 않고 공식 클라이언트가 저장한 로그인을 사용합니다.
- 로그인이 유효한 동안에는 서비스 앱·CLI를 사용 중일 필요가 없습니다. 로그인 취소·창 닫기·5분 제한 시간에는 모니터가 시작한 로그인 프로세스만 종료하며, 기존 사용 중인 앱·CLI는 종료하지 않습니다.

로그인 명령과 공식 브라우저 흐름은 [Codex 인증 문서](https://learn.chatgpt.com/docs/auth)와 [Claude Code CLI 문서](https://code.claude.com/docs/en/cli-reference)를 따릅니다. 회사 보안 설정 등으로 로컬 로그인 콜백이 차단되거나 별도 코드 입력을 요구하는 환경에서는 이 브라우저 연결 도우미가 완료되지 않을 수 있습니다.

카운트다운은 매초 다시 그립니다. 초기화 시각을 지났더라도 서버에서 새 한도를 확인하기 전에는 임의로 100%를 표시하지 않습니다. 세부 초기화 날짜와 마지막 조회 시각은 서비스 영역에 마우스를 올리면 한국 시간으로 볼 수 있습니다.

## Gemini 실험적 연결

연결 관리 또는 트레이에서 Gemini를 켜면 같은 방식으로 칸을 표시하고, 끄면 조회를 멈추고 칸을 숨깁니다. 처음에는 꺼져 있습니다. 기존 `%USERPROFILE%\.gemini\oauth_creds.json`의 로그인 토큰을 읽어 공식 CLI 공개 코드의 `loadCodeAssist` HEALTH_CHECK 및 `retrieveUserQuota` 경로로 조회를 시도합니다. 프로젝트 생성·온보딩·AI 모델 호출은 하지 않습니다. 프로젝트는 `GOOGLE_CLOUD_PROJECT` 또는 `GOOGLE_CLOUD_PROJECT_ID`로도 지정할 수 있습니다.

이 API는 **CLI/Code Assist 모델 한도**이며 Gemini 웹·앱 구독의 5시간·주간 한도와 같다고 확인되지 않았습니다. API에 잔여 비율과 초기화 시각이 있으면 그대로 표시합니다. Pro·Flash 계열별로 남은 비율이 가장 낮은 실제 버킷을 보수적으로 표시하고, 구체적인 모델명과 종류는 툴팁에서 확인할 수 있습니다. 해당 계열이 없으면 실제 모델 한도 최대 두 개를 표시합니다. 수치가 없거나 API가 거부하면 미제공·연결 불가 상태를 표시하며 임의 수치를 만들지 않습니다.

Gemini의 브라우저 로그인은 Node.js/npm으로 설치된 공식 Gemini CLI의 인증 모듈을 사용합니다. 현재 지원하지 않는 설치 형태·암호화된 저장 방식·Google 계정/프로젝트 권한에서는 연결이 되지 않을 수 있습니다. 로그인 토큰을 직접 갱신하거나 로그인 파일을 수정하지 않으므로 만료되면 공식 로그인으로 다시 연결해야 합니다.

**2026-10-28 Gemini 추가 빌드는 사용자 요청으로 테스트·앱 실행·실계정 API 조회를 수행하지 않았습니다. 컴파일 성공만 확인한 실험적 기능입니다.**

참고: [공식 quota 호출 코드](https://github.com/google-gemini/gemini-cli/blob/main/packages/core/src/code_assist/server.ts), [공식 quota 응답 정의](https://github.com/google-gemini/gemini-cli/blob/main/packages/core/src/code_assist/types.ts).

| `×` | 프로그램 종료 |
| 트레이 아이콘 더블클릭 | 창 복원 |
| 트레이 아이콘 우클릭 | 관리 메뉴 |

캐릭터 크기에는 상한이 없습니다. 창 크기는 유지되며, 창보다 크게 키운 부분은 잘려서 표시됩니다. 크기 조절 버튼은 캐릭터 위에 표시되어 계속 사용할 수 있습니다.

## 릴리스 설치와 업데이트

처음 설치할 때는 카톡으로 받은 ZIP을 쓰기 가능한 사용자 폴더에 풀고 EXE를 실행합니다. 1.3.1부터는 실행할 때와 실행 중 10분마다 자동으로 업데이트를 확인합니다. 배포판의 Claude 연결은 Claude Code 로그인을 사용합니다. Windows x64용 단일 실행 파일이며 .NET을 별도로 설치할 필요가 없습니다. `AI Usage Monitor.exe`라는 이름으로도 실행·업데이트할 수 있습니다.

트레이 아이콘을 우클릭해 **최신 버전 업데이트…**를 선택하면 현재 버전보다 높은 정식 릴리스를 확인합니다. 자동 확인에서 새 버전을 찾으면 승인 없이 다운로드하고 GitHub API가 제공한 파일 크기와 SHA256 digest를 확인한 뒤, 앱이 종료된 후 현재 EXE만 교체하고 다시 실행합니다. 서비스 로그인 파일과 설정은 업데이트 대상이 아닙니다. 수동 확인 버튼도 계속 사용할 수 있습니다. 자동 조회에 실패하면 다음 확인 때 재시도합니다.

업데이트는 `zqxw116/AI-Usage-Monitor`의 `v숫자.숫자.숫자` 정식 릴리스와 지정된 Windows 자산만 허용합니다. SHA256이 없거나 일치하지 않으면 설치하지 않습니다. 다운로드 이동은 HTTPS GitHub 자산 서버로 제한합니다. SHA256은 전송된 파일이 GitHub 릴리스와 일치하는지 확인하는 수단이며, 배포자 코드 서명을 대신하지 않습니다. digest 필드는 [GitHub 공식 Releases API](https://docs.github.com/en/rest/releases/releases#get-the-latest-release)를 사용합니다.

EXE 폴더에 쓰기 권한이 없으면 앱을 종료하기 전에 실패 안내를 표시합니다. 관리자 권한 승격은 요청하지 않습니다. 교체 실패는 기존 EXE를 유지하며, 교체 후 새 프로세스 시작에 실패하면 백업을 복구하고 기존 버전을 다시 시작합니다. 새 프로세스가 실행된 뒤 발생하는 런타임 오류까지 자동 감지하지는 않습니다. 도우미 실행 뒤의 실패 상세와 백업은 EXE 옆 `.ai-usage-update-*` 폴더에서 확인할 수 있습니다. 다운로드 중 실패하면 현재 앱은 계속 실행됩니다.

### 버전 태그 배포

배포 전 `src/UsageMonitor.csproj`의 `Version`을 올리고 같은 버전의 `vMAJOR.MINOR.PATCH` 태그를 원격 저장소에 게시합니다. 태그 게시에는 별도 사용자 승인이 필요합니다. 예를 들어 프로젝트 버전 `1.1.0`에는 `v1.1.0`을 사용합니다.

`.github/workflows/release.yml`은 태그·프로젝트 버전 일치 확인, 합성 업데이트 검사, 임시 EXE 교체·재시작 검사, Windows x64 독립 실행 빌드를 수행합니다. 빌드 성공 후 `AI-Usage-Monitor-win-x64.exe`와 `SHA256SUMS.txt`를 초안 릴리스에 올리고, GitHub가 계산한 digest와 빌드 결과 해시가 같을 때 정식 최신 릴리스로 공개합니다. 검증 실패 시 초안을 남깁니다. 재실행 전 기존 초안과 실패 원인을 확인해야 합니다. 워크플로 파일 추가만으로 태그나 릴리스가 게시되지는 않습니다.

업데이트 검사는 실제 계정이나 모니터 실행 없이 수행할 수 있습니다.

```powershell
dotnet run --project 'tests\Updates\Updates.csproj' -c Release
& '.\tests\Updates\InstallerChecks.ps1'
```

## 로컬 빌드

Windows에 .NET 9 SDK를 설치한 뒤 **`빌드.bat`를 더블클릭**하면 됩니다. 배포 폴더에서 실행 중인 모니터를 종료하고, 같은 폴더의 `AI Usage Monitor.exe`와 `AI Usage Monitor.zip`을 교체합니다. 받는 사람에게는 ZIP 하나를 보내세요.

빌드가 끝나면 결과 폴더가 열립니다. 그 안의 **`AI Usage Monitor.exe`**를 실행하세요. SDK가 없거나 빌드가 실패하면 배치 창에 안내가 표시됩니다. 빌드 결과의 EXE가 실행 중이면 종료한 뒤 다시 빌드하세요.

배치파일은 저장소의 `src` 폴더와 기존 개인 작업 폴더의 `소스` 폴더를 모두 지원합니다. 다른 작업 폴더에서 실행해도 배치파일이 있는 위치를 기준으로 빌드합니다.

명령어로 실행하려면 저장소 폴더에서 PowerShell을 열어 다음과 같이 입력합니다.

```powershell
dotnet publish ".\src\UsageMonitor.csproj" -c Release -o ".\artifacts\publish" -p:RuntimeFrameworkVersion=9.0.11 -p:NuGetAudit=false
```

결과: `artifacts\publish\AI Usage Monitor.exe`

기본 빌드는 .NET 실행 환경을 포함한 단일 EXE입니다. 대상 PC에 .NET을 따로 설치할 필요가 없는 대신 실행 파일 크기는 약 110MB입니다. 이미지 자산은 약 2MB이며 나머지 대부분은 실행 환경입니다. EXE와 빌드 중간 파일은 Git에 포함하지 않습니다.

실행 환경이 이미 설치된 PC를 위한 작은 빌드는 다음과 같이 만들 수 있습니다. 이 빌드를 실행하려면 .NET 9 **Windows Desktop Runtime x64**가 필요합니다.

```powershell
dotnet publish ".\src\UsageMonitor.csproj" -c Release -o ".\artifacts\framework-dependent" --self-contained false -p:IncludeNativeLibrariesForSelfExtract=false -p:RuntimeFrameworkVersion=9.0.11 -p:NuGetAudit=false
```
